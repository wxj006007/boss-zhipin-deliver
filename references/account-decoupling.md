# 账户、浏览器连接与投递业务解耦

状态：implemented（实现与独立审查完成；保留既有 Git 历史，正常追加提交发布）

## 问题与目标

原实现自 `e9e736c` 引入多账户时，将账户身份、数据目录与浏览器类型、端口、session 一起永久注册；`a4c7425` 增加跨账户并行后保留该规则。它避免了串号、端点争用和重复去重历史，但把运行期间的连接独占扩大为永久归属。

目标：支持任意本地账户；同一身份可在结束一轮后换连接，历史保持不变；不同身份可顺序复用同一连接。并行仍要求独立端点。新版本源文件只有代码、空白模板和合成测试数据；用户明确接受既有 Git 历史中的旧内容，不清理或改写历史。

非目标：自动登录或切换网站账户、用 session 隔离 Cookie、修改现有本机个人数据、发送真实消息、擅自重写远端历史。

## 方案

- `accounts.py` 维护本地账户身份、历史归属、注册及租约锁，不依赖投递模块。
- 独立连接配置只描述 browser / bridge / session。`--connection` 在启动时选择连接，不写入账户永久注册。
- `execution_context.py` 是投递业务消费的运行契约：只读本轮配置与画像快照、检查租约与路由、取得数据目录和来源标记；不读取账户注册表、不管理账户。
- 浏览器适配器负责实际页面身份校验；投递模块不依赖账户管理实现。
- 统一 runner 负责装配账户、连接和投递命令。旧混合配置继续作为连接默认值读取；新配置使用独立文件。
- 注册表只约束别名、身份和历史目录。连接独占由 begin 到 end 的活动租约及命令级端点锁保证；切换连接必须先 end。错误身份仍在读取和发送边界拒绝。
- 文档以通用安装与配置为主，移除本机路径、真实履历和发送样例；保留空白模板。发布检查针对当前源文件，历史扫描仅供审计，不以历史发现阻止正常追加提交。

## 替代方案

仅删除注册字段校验虽能换浏览器，但业务仍依赖账户管理且会失去 begin/end 期间的端点归属保护，因此不采用。永久将端点注册给账户会继续阻碍顺序复用，也不采用。

## 已执行证据

- `python -m unittest discover -s tests -q`：原 134 项与新增连接/发布测试通过。最终将默认账户控制目录指向含 enabled.json 的合成临时目录再运行同一 discover：149 项通过，零失败、零错误、零跳过。使用合成身份、真实子进程和本地假桥接，没有真实网站发送。
- `python tools/check_publication.py`：当前工作源文件检查无发现。该检查不能证明任意自然语言中完全不存在个人信息，另进行内容审查。
- 历史检查按每个可达提交的树枚举全部 blob/path 组合，防止同内容改名漏检。当前本机分支、标签和远端跟踪引用共有 142 个组合；检查发现 28 项个人路径/旧专属文本，涉及 6 个文件路径。没有发现实际账户配置/投递历史文件路径。检查不连接远程，不覆盖服务器未被本地引用的对象或外部缓存。
- 当前源文件另用本机两账户的身份与画像、旧个人专属文本作为只读比对输入，检查无发现。人工审查发现的历史姓名、账户专属学历偏好和本机路径均已在当前版本泛化。
- 用户已明确选择保留既有 Git 历史。按正常提交和推送发布，不强推、不创建替代仓库，也不宣称历史已脱敏。源文件导出仍可作为不含 `.git` 的可选分发形式。
- 验证期间未修改已安装主目录的账户、连接、投递历史或运行状态；发布只更新受版本控制的代码和说明。
- 独立 Reviewer 检查完整变更后未发现剩余阻断问题。审查发现的历史同 blob 改名漏检、旧测试控制目录隔离遗漏、文档固定 A/B 开场和个人内容均已修复；Reviewer 独立复验发布测试 4 项、已启用账户环境中的发送测试 32 项及源文件扫描。
- 技能 quick_validate、Markdown 本地链接检查、git diff --check 均通过。真实浏览器、扩展连接和网站 DOM 未在本次验证，不能把模拟验证表述为实投通过。

## 升级边界

旧混合账户配置的显式 workdir 继续有效；旧单账户的机器专属隐式目录已移除。旧单账户升级前必须显式设置原 BOSS_WORKDIR 或相应 --workdir，防止忽略历史已投与 uncertain。未自动移动或清空任何数据。
